# URL → Markdown → LLM

웹 페이지 URL을 붙여넣으면 본문을 Markdown으로 변환해 보여 주고, 복사·다운로드하거나 ChatGPT·Claude로 바로 넘기는 단일 화면 서비스.

## 사용자에게 보이는 결과

한 화면에서 아래 순서로 진행합니다. 계정, 저장, 이력은 없습니다.

1. **입력**: URL을 붙여넣고 변환을 실행합니다. 지우기 버튼은 입력과 결과를 모두 초기 상태로 되돌립니다.
2. **변환**: 페이지 본문을 Markdown으로 추출합니다.
3. **결과 확인**: 페이지 제목과 저자를 담은 헤더가 위에, 렌더링된 Markdown이 아래에 나옵니다.
4. **내보내기**: 복사하기, `.md` 다운로드, ChatGPT로 열기, Claude로 열기.

화면의 모든 문구는 한국어입니다. 헤더 오른쪽 위에 다크모드 토글이 있습니다.

## 승인된 범위

- URL 입력, 지우기, 변환
- 제목·저자 헤더와 렌더링된 Markdown 결과
- 복사하기, `.md` 다운로드
- ChatGPT·Claude로 열기와 선택적 프롬프트 (프리셋 3종 + 직접 입력)
- 라이트/다크 테마 토글
- 로딩, 오류, 빈 상태 (아래 수용 기준 참조)

## 동작 규칙

### 변환

- 본문 추출과 Markdown 변환은 **defuddle 라이브러리**로 합니다(필수 요구). 외부 호스팅 API(defuddle.md)가 아니라 이 앱이 라이브러리를 직접 실행합니다.
- 브라우저는 다른 사이트의 HTML을 직접 가져올 수 없으므로, 페이지 가져오기와 변환은 이 앱의 서버 쪽에서 합니다.
- `http`·`https` URL만 받습니다. 그 외 입력은 변환 전에 형식 오류로 안내합니다.
- 헤더의 저자는 추출되지 않으면 해당 줄을 숨깁니다(빈 값이나 "undefined"를 노출하지 않음). 제목이 없으면 URL의 호스트를 대신 보여 줍니다.
- defuddle은 본문 첫머리의 제목을 중복으로 판단해 본문에서 빼므로, 제목은 헤더로만 보입니다. 복사·다운로드되는 Markdown에도 이 동작을 그대로 따릅니다.

### 결과 표시

- Markdown은 서식이 적용된 형태(제목, 목록, 링크, 코드 등)로 렌더링합니다. 본문 안의 원시 HTML은 실행되거나 그대로 삽입되지 않습니다.
- 결과 영역은 읽기 전용입니다. 편집 기능은 없습니다.

### 내보내기

- **복사하기**: 변환된 Markdown 본문을 클립보드에 넣고, 성공했음을 버튼 상태 등으로 알립니다.
- **.md 다운로드**: 변환된 Markdown을 `.md` 파일로 저장합니다. 파일명은 페이지 제목에서 만들고, 제목이 없으면 호스트를 씁니다.
- 복사·다운로드에는 프롬프트가 포함되지 않고 Markdown 본문만 담깁니다.
- **ChatGPT로 열기 / Claude로 열기**(확정된 전달 방식, 클립보드 방식):
  1. 본문 Markdown을 클립보드에 복사합니다.
  2. 해당 서비스를 새 탭으로 엽니다. 프롬프트를 골랐다면 그 문장만 입력창에 미리 채워 열고, 고르지 않았다면 빈 새 대화로 엽니다.
  3. 화면에 "본문이 복사되었습니다. 입력창에 붙여넣기(⌘V / Ctrl+V) 하세요"라는 안내를 보여 줍니다.
- 본문이 URL에 실리지 않으므로 글 길이와 상관없이 같은 방식으로 동작합니다.

### 프롬프트

- 프리셋은 **요약해줘 / 한국어로 번역해줘 / 쉽게 설명해줘** 3가지이고, 그 옆에 **직접 입력** 선택지가 있습니다.
- 기본 선택은 "프롬프트 없음"입니다. 프롬프트는 선택 사항이며, 고르지 않으면 앞에 붙는 문장이 없습니다.
- "직접 입력"을 고르면 텍스트 입력란이 나타나고, 다른 선택지로 바꾸면 사라집니다.
- 직접 입력한 문장은 **1회용**입니다. 저장하지 않으며 새로고침하면 사라집니다. 지우기 버튼도 직접 입력 내용을 비웁니다.
- 프롬프트는 "ChatGPT·Claude로 열기"에서만 쓰입니다.

### 다크모드

- 첫 방문 시 OS 설정을 따르고, 토글로 라이트/다크를 바꿀 수 있습니다. 사용자의 선택은 다음 방문에도 유지됩니다.

## 수용 기준

1. 유효한 기사 URL을 넣고 변환하면 제목·저자 헤더와 렌더링된 Markdown이 나타난다.
2. 변환 중에는 로딩 상태가 보이고 중복 실행이 되지 않는다.
3. 지우기 버튼을 누르면 입력, 결과, 직접 입력 문장이 모두 비워지고 초기 화면으로 돌아간다.
4. `http`·`https`가 아닌 입력, 가져오기 실패(접속 불가, 비정상 응답), 본문 추출 결과가 비어 있는 경우에는 각각 원인이 구분되는 한국어 오류 안내가 나오고 이전 결과는 남지 않는다.
5. 복사하기를 누르면 클립보드의 내용이 화면에 보이는 결과의 Markdown과 같다.
6. 다운로드한 `.md` 파일의 내용이 복사 결과와 같다.
7. 프롬프트를 고르고 ChatGPT(또는 Claude)로 열기를 누르면 새 탭이 열리고, 입력창에 선택한 프롬프트가 채워지며, 클립보드에는 본문이 들어 있고 붙여넣기 안내가 보인다.
8. 프롬프트를 고르지 않으면 프롬프트 없이 빈 새 대화가 열리고 같은 안내가 보인다.
9. 직접 입력을 선택하면 입력란이 나타나고, 입력한 문장이 열기 시 사용된다. 새로고침 후에는 남아 있지 않다.
10. 다크모드 토글이 즉시 반영되고, 새로고침 후에도 선택이 유지된다.
11. 좁은 화면(휴대폰 폭)에서도 모든 동작이 숨겨지지 않고 순서대로 쌓여 쓸 수 있다.

## 확정된 제약과 근거

| 제약 | 근거 |
|---|---|
| defuddle 라이브러리를 서버 쪽에서 직접 실행 | 사용자의 필수 요구. 호스팅 API는 무료 한도 이후 유료·키 필요이고, 브라우저의 직접 가져오기는 CORS로 막힘 |
| LLM으로 열 때 본문은 클립보드, 프롬프트만 URL | 사용자가 확정. Markdown이 길면 URL에 담을 수 없으므로 길이와 무관하게 동작하는 쪽을 선택 |
| UI는 [ui-composition](../../decisions/ui-composition.md) 계약을 따름 | 일반 UI는 shadcn 구성, semantic token, 공통 shell, 상태(loading/empty/error/success/disabled) 설계, 좁은 화면 stacking을 이 계약이 정함 |

앱 수준의 `PRODUCT.md`는 없으므로 이 스펙이 전제로 삼는 상위 제약은 없습니다.

## 가정 (에이전트가 정한 기본값, 바꿔도 되는 것)

- 프롬프트 기본 선택은 "없음"이고, 프롬프트는 복사·다운로드에 섞이지 않는다.
- 지우기는 프리셋 선택은 유지하고 직접 입력 문장만 비운다.
- ChatGPT는 `https://chatgpt.com/?q=…`, Claude는 `https://claude.ai/new?q=…` 형식으로 프롬프트를 채우는 것으로 가정한다. 샌드박스가 외부 접속을 막아 이번 세션에서 두 주소의 실제 동작은 확인하지 못했다.
- 테마 선택 저장은 브라우저 로컬 저장소를 쓴다.
- 결과에 원문 URL과 사이트명을 헤더의 보조 정보로 함께 보여 줘도 된다(제목·저자 외 추가는 선택).

## 범위 밖과 이유

- 계정, 변환 이력, 서버 측 저장: 요구에 없고 "저장하지 않음" 방향과 맞지 않음
- 로그인이 필요한 페이지, 자바스크립트로만 그려지는 페이지의 변환 보장: 서버가 가져온 HTML만 대상으로 함
- 결과 편집, 여러 URL 일괄 변환, 프롬프트 저장·관리
- 외부 서비스에 대한 SSRF 방어, 속도 제한 같은 보안 하드닝: 스펙이 요구하지 않으므로 프로젝트 검증 예산상 범위 밖

## 남은 위험

- **LLM 사이트의 `?q=` 동작이 바뀔 수 있음**: 두 서비스가 쿼리 미리 채우기를 바꾸거나 제한하면 프롬프트가 채워지지 않는다. 이때도 본문은 클립보드에 있으므로 사용자가 직접 붙여 넣어 쓸 수 있다. 구현 시 실제 동작을 한 번 확인해야 한다.
- **일부 사이트는 봇 차단이나 동적 렌더링으로 본문이 비거나 부실할 수 있음**: 오류 안내(수용 기준 4)로만 대응한다.
- **붙여넣기 단계가 한 번 더 필요함**: 클릭 한 번으로 끝나지 않는 대신 길이 제한을 피한 선택이다.
- defuddle 0.19.5와 linkedom 조합에서 로컬 HTML 변환이 되는 것까지만 확인했다. 실제 외부 페이지 변환은 구현 단계 런타임 검증에서 확인한다.
